3. FRAMEWORK DE PERMISSÕES
================================================================================

IMPLEMENTADO:
✅ allowed-operations.json — whitelist de comandos PowerShell
✅ operation-registry.js — valida e compila templates parametrizados
✅ sanitizeToolArgument() — regex ^[a-zA-Z0-9_. -]{1,128}$
✅ /classify — classificação de operações destrutivas

PONTOS FORTES:
• Single source of truth em allowed-operations.json
• Geração dinâmica de schemas MCP a partir de {{PLACEHOLDER}}
• Rejeição (não stripping) de input inválido

GAPS:
• Permissões não granulares por tipo de cliente
• Sem rate limiting por usuário/token

ARQUIVOS-CHAVE:
• v10/allowed-operations.json
• v10/operation-registry.js
• mcp-server/security.js

================================================================================
7. SEGURANÇA DE REDE
================================================================================

CAMADAS IMPLEMENTADAS:
1. CORS — Origin deve igualar MESTRE_BASE_URL (exceto MCP)
2. Headers — X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer
3. CSP — frame-ancestors 'none' previne clickjacking
4. Tokens — X-Mestre-Extension-Token, X-Mestre-Npp-Token

REGRAS DE OURO:
• Nunca restaurar acesso file:// à UI (sempre http://127.0.0.1:7777)
• MCP não envia Origin; clientes HTTP devem validar
• Tokens gateiam integrações (extension, NPP)

ARQUIVOS-CHAVE:
• v10/launcher.js

CONCLUSÃO
================================================================================

O documento PDF consolida uma arquitetura MADURA EM PRODUÇÃO para o núcleo MCP
local, com ROADMAP CLARO para:

1. Expansão multi-LLM (Remote Gateway)
2. UI de gerenciamento MCP (Menu 🔌)
3. Governança formal de dependências (inventário, política, CI)
4. AI Headless (agente CLI Python + Ollama)

PRINCIPAIS RISCOS MITIGADOS:
✅ Whitelist estrita de comandos
✅ Sanitização com rejeição (não stripping)
✅ Prompt injection detection
✅ Auditoria com redação de sensíveis
✅ Separação MCP (não-elevado) / Launcher (elevado)

RISCOS RESIDUAIS:
⚠️ @hono/node-server vulnerável mas não usado (requer documentação)
⚠️ mysql2 no core path (deveria ser opcional)
⚠️ Overrides sem justificativa registrada (difícil auditar)
