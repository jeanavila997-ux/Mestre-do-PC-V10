1. Resumo Executivo

O Mestre do PC V10/V11 é um ecossistema completo de automação, manutenção e diagnóstico para ambientes Windows 10/11. Desenvolvido por Jean Carlos sob licença MIT, o projeto expõe operações administrativas de PowerShell de forma segura e controlada através de múltiplas interfaces: uma aplicação web SPA, um servidor MCP (Model Context Protocol) para integração com assistentes de IA como Claude Desktop e GitHub Copilot, uma extensão de navegador (Chrome/Firefox) e um plugin para Notepad++.

🔒 Premissa Fundamental de Segurança
Clientes de IA nunca executam código de shell diretamente. Todo e qualquer comando administrativo é validado contra uma whitelist estrita (allowed-operations.json) antes de ser executado pelo sistema. Argumentos são sanitizados com regex ancorada e rejeição total de caracteres perigosos.

O sistema opera em uma arquitetura de três camadas: os clientes (UI, IA, extensões) comunicam-se via HTTP REST ou MCP stdio com o backend Node.js (launcher.js, porta 7777), que por sua vez valida, resolve e executa comandos PowerShell em ambiente isolado e seguro. A IA local é fornecida pelo Ollama (local ou cloud), com suporte a 13 modelos LLM catalogados, RAG, Chain-of-Thought e análise de código.

5. Backend — Launcher (v10/launcher.js)

O launcher.js é o coração do sistema — um servidor HTTP Node.js puro (898 linhas) que escuta em 127.0.0.1:7777 e atua como gateway de segurança entre todos os clientes e o subsistema Windows.

Responsabilidades Principais

  • Autorização Multi-Cliente: Valida o header X-Mestre-Client (v10-web, mcp, browser-extension, notepad-plus-plus) e tokens de autenticação por integração.
  • Execução Segura de Comandos: Resolve operações via OperationRegistry, executa PowerShell com ambiente limpo (cleanPSEnv(), -NoProfile -ExecutionPolicy Bypass).
  • Jobs Assíncronos: Map em memória com limite de 3 jobs simultâneos, timeout de 15 minutos e retenção de 30 minutos.
  • Proxy Ollama: Streaming NDJSON transparente para modelos locais (porta 11434) ou cloud, com guard de prompt injection na última mensagem do usuário.
  • Modo Livre: Toggle opt-in persistido em logs/config/modo-livre.json; quando ativo, aceita qualquer comando PowerShell com auditoria de nível SECURITY.
  • Roteamento Modular: Delega rotas /api/* para chat-integrado/api-routes.js, /memories/* para memory-routes.js e ações Notepad++ via /npp.
  • Servir Estáticos: Serve a SPA index.html com fallback para rotas de seção, protegendo contra path traversal.

Headers de Segurança em Toda Resposta

X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Cache-Control: no-store
Content-Security-Policy: ... frame-ancestors 'none' ...

v10/operation-registry.js — 207 linhas

Classe OperationRegistry — a Fonte Única da Verdade compartilhada entre o launcher e o MCP server:

  • resolve(body) — aceita {id, params} ou {cmd}, valida contra whitelist e retorna comando seguro ou erro.
  • buildMcpToolRegistry() — gera dicionário de ferramentas MCP.
  • buildMcpToolSchemas() — gera JSON Schema para cada ferramenta MCP.
  • validate() — verifica integridade do catálogo (IDs duplicados, campos obrigatórios).

8. Segurança e Sanitização

🛡️ Modelo de Segurança: Defense-in-Depth
O Mestre do PC implementa múltiplas camadas de proteção sobrepostas. Mesmo que uma camada falhe, as demais garantem a integridade do sistema.

8.1. Sanitização de Argumentos (sanitizeToolArgument)

AspectoImplementação
Regex permitida/^[a-zA-Z0-9_. -]+$/
Tamanho1 a 128 caracteres
FilosofiaRejeição total (retorna null), nunca filtragem silenciosa
Bloqueados; | & ` $() " ' \n e qualquer caractere de controle

8.2. Detecção de Prompt Injection (checkPromptInjection)

Motor heurístico ponderado com score de 0.0 a 1.0:

Padrão DetectadoPeso
ignore previous instructions0.90
forget instructions0.85
bypass rules/safety/security0.85
Persona override (you are now, from now on)0.80
System prompt leak / DAN mode0.75
Delimitadores de sistema (<<<system>>>, [inst])0.70
Quebras de linha suspeitas com comandos0.55
Caracteres de controle binários/nulos0.40
ScoreClassificaçãoAção
≥ 0.70🔴 MaliciosoRequisição bloqueada, erro retornado, evento auditado em nível SECURITY
0.35 – 0.69🟡 SuspeitoPermitido, porém logado em auditoria SECURITY
< 0.35🟢 BenignoExecução normal

8.3. Outras Camadas

  • Header obrigatório: Toda comunicação com o launcher exige X-Mestre-Client.
  • Tokens por integração: MESTRE_EXTENSION_TOKEN (extensão), MESTRE_NPP_TOKEN (Notepad++).
  • CSP restritivo: frame-ancestors 'none', proteção contra XSS e clickjacking.
  • Ambiente PowerShell limpo: cleanPSEnv() reconstrói PSModulePath para evitar poluição por PS7 MSIX.
  • Modo Livre auditado: Quando ativo, todo comando livre é registrado em nível SECURITY.
  • Prompt Guard Server opcional: Microserviço Python (porta 7778) usando modelo meta-llama/Prompt-Guard-2-86M.

10. Módulos de Chat e IA

O projeto possui dois sistemas de chat complementares:

10.1. Chat IA Modular (v10/chat/)

  • chat-module.js (1.462 linhas): Classe MestreChat com UI flutuante/minimizável, streaming NDJSON, gravação por voz (Web Speech API), anexos de contexto (dashboard, arquivos, imagens multimodais, terminal), memórias IndexedDB e modais de confirmação de segurança.

10.2. Chat Integrado Corporativo (v10/chat-integrado/)

  • db.js (275 linhas): Camada SQLite local usando node:sqlite (Node 22) com tabelas para conversas, mensagens, memórias, auditoria e config em modo WAL.
  • mysql-sync.js (195 linhas): Sincronização SQLite → MySQL remoto (ex: Hostinger) com threshold automático de 500 registros.
  • api-routes.js (364 linhas): Roteador HTTP /api/* desacoplado para tools, perfis, conversas, memórias, auditoria e web search.
  • tools-api.js (558 linhas): Mapeia 24 ferramentas MCP para funções executáveis via HTTP.
  • web-search.js (214 linhas): Busca web via Ollama Cloud (web_search/web_fetch) ou fallback DuckDuckGo HTML scraping.
  • chat-integrado.js (854 linhas): Frontend com sidebar de conversas, seleção de perfis e renderização Markdown.

22. Conclusão e Recomendações

✅ Pontos Fortes
  • Segurança Exemplar: Modelo Defense-in-Depth com whitelist estrita, sanitização por rejeição, detecção de prompt injection, headers HTTP restritivos, auditoria completa e separação de privilégios.
  • Arquitetura Modular e Extensível: Separação clara de responsabilidades entre launcher, MCP server, registry, módulos de chat, memórias e dashboard. Novos clientes podem ser adicionados facilmente.
  • Fonte Única da Verdade: O allowed-operations.json centraliza todas as operações permitidas, consumido tanto pelo launcher quanto pelo MCP server via operation-registry.js.
  • Documentação Extensa: 44+ documentos cobrindo arquitetura, segurança, instalação, modelos IA, integrações e guias rápidos — todos em Português e Inglês.
  • Testes Robustos: 12 arquivos de teste Node.js focados em invariantes de segurança + 8 smoke tests Python + 8 planos de teste UI.
  • Mínimas Dependências: O projeto evita inchar o node_modules — apenas 2 dependências diretas (SDK MCP e mysql2).
  • Multi-Interface: Web SPA, MCP (Claude/Copilot), extensão Chrome/Firefox e plugin Notepad++ — todos usando os mesmos endpoints e garantias de segurança.
⚠️ Observações e Oportunidades de Melhoria
  • Cobertura de Testes: Não há ferramenta de cobertura configurada (ex: c8, istanbul). Adicionar métricas de cobertura permitiria identificar áreas não testadas.
  • Tamanho dos Arquivos Principais: mcp-server/index.js (2.080 linhas) e v10/index.html (2.792 linhas) são arquivos muito grandes. Considerar modularização adicional para facilitar manutenção.
  • TypeScript: O projeto é 100% JavaScript. Para um projeto dessa complexidade, TypeScript poderia melhorar a segurança de tipos e a experiência de desenvolvimento.
  • Linting Formal: Não há configuração de ESLint ou Prettier. Adicionar linting formal garantiria consistência de estilo de código.
  • Rate Limiting: Embora o launcher seja local (127.0.0.1), rate limiting explícito nas rotas poderia fornecer uma camada adicional de proteção.
  • Testes E2E Automatizados: Os planos TestSprite são declarativos mas parecem não ter execução automatizada integrada ao CI.
